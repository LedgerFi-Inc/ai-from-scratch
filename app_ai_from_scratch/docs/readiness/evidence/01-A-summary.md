Cycle 1 Track A hardened the payments revenue path so an `approved` Mercado Pago payment no longer grants access on status alone. Checkout now mints a single-use `checkout_orders` row (24 h expiry on the preference, `external_reference` = `order_key`) before talking to Mercado Pago; `assessPayment` refuses test-mode/live mismatches, currency drift, underpayment, reused one-time orders, and payments with no resolvable user; those last land `dead` as `orphan_payment:<id>` instead of retrying. Webhooks are classified (`payment` / `subscription` / `authorized_payment` / ignore), the signature manifest lowercases alphanumeric ids and drops an empty `request-id` segment, and `subscription_authorized_payment` is processed through the same assess+grant path. `/health` and `/v1/admin/payments` expose queue/orphan counts; a 15-minute reconcile plus `POST /v1/admin/reconcile` re-enqueues drifted ids; `POST /v1/admin/redrive` revives dead events except permanent `orphan_payment:` / `no_order` / `order_consumed`. Entitlement now returns `grantId`/`grantAmountMinor` for the thank-you page, skips `eligible:false` rows, and filters SQL by `(kind, provider_id)` so one unparsable `date_approved` cannot block another grant. `pnpm --dir payments check && pnpm --dir payments test` is green (57 tests). `PAYMENTS_TEST_DATABASE_URL` was unset, so migrate-idempotence, concurrent `consumeOrder`, and the orphan dead-letter path were not proved against Postgres. Mercado Pago's `GET /authorized_payments/{id}` response is documented as an invoice whose **payment id is the nested `payment.id`** (example: `"payment": { "id": 19951521071, "status": "approved" }`); the invoice's own top-level `id` is a different identifier. The implementation reads `payment.id` first and falls back to top-level `id` with a warning if neither is present — we did not call the live API.
